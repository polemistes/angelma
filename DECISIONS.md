# Decisions

Choices made where `PLAN.md` was ambiguous or silent. One line each.

- The site is assumed to live at the web root (as on Domeneshop's `www/`); URLs are root-relative and no base-path detection is done.
- `robots.txt` is served directly by `.htaccess` as well, otherwise it would fall through to `index.php` and give 404.
- Composer `platform.php` is pinned to 8.2.0 so the committed `vendor/` works on any PHP 8.2+ host; PHPUnit 11.5 is used.
- `dev/router.php` serves static files itself (instead of returning false) so the security headers are set on them too, as Apache does.
- `slugify()` follows the test case in step 1.2 (`Blåbærsyltetøy` → `blabaersyltetoy`): æ → ae, ø → o, å → a. Section 9's "ae oe aa" contradicts that example; the example wins.
- `app/bootstrap.php` sets everything up; `index.php` then dispatches the request. This lets the installer include the bootstrap without dispatching.
- Small extra core classes not in the folder list: `App` (state and request cycle), `Request`, `Response`, `HttpException`, and `app/routes.php` for the route table.
- An unknown path gives 404; a path that only has routes for another method gives 405. GET `/logout` gives 404, because a GET for any single segment is looked up as a page slug.
- Sessions start only after installation; the session lifetime is the browser session, server-side garbage collection after 24 hours of inactivity.
- The security headers other than CSP come from `.htaccess` (as section 8 says) and `dev/router.php`, not from PHP, to avoid duplicate headers.
- Referential integrity is handled in the Repos (deletes run in transactions), not with SQL foreign-key constraints, so deletes follow the rules of section 6.12 exactly.
- Table and column names follow section 4 exactly. Note for a later MySQL driver: `rows` and `key` are reserved words there and will need quoting.
- Login attempts get their own repo, `Repos/LoginAttempts.php`, because all SQL must live in a repo. `Repos/Repo.php` is a small shared base class.
- Usernames are stored and compared in lower case, so login is case-insensitive.
- Deleting a user moves their pages, blogs, images and posts to the administrator who deletes them; their comments keep the author name but lose the user link.
- Published posts are shown regardless of `published_at` being in the future (scheduled publishing is a later feature).
- The `Schemes` class and the five scheme files were created in step 1.4 instead of 1.5, because the installer's site step needs the list of built-in schemes.
- The installer logic lives in `app/Installer.php` (testable); `install/index.php` is only the page flow. It has its own `install/install.css` and `install/install.js` (no inline scripts, because of the CSP).
- The installer stores only the password hash in the session between steps, never the plain password.
- If `installed.lock` is missing but the database already contains users, the installer refuses to continue instead of overwriting the site.
- Usernames: 3 to 40 letters, digits, dots, dashes or underscores. Display names: at most 80 characters.
- The page's `title` is used for `<title>` and as a visually hidden `<h1>`; visible headings come from the boxes (the installer's welcome box already has its own heading). This keeps one `<h1>` per page.
- The home page is reachable both as `/` and as `/{its slug}`; the menu links to `/`.
- Row alignment: a row's grid gets only as many 1/12-wide columns as its boxes use, so `justify-content` can place them left, centre or right. Empty rows are not shown publicly.
- On narrow screens fixed heights are dropped for text boxes only (as the plan says); image, blog and embed boxes keep them.
- `--page-width` is written into the same `<style>` block as the scheme colours. `app/Frame.php` gathers the data for the public page frame (settings, menu, logo, footer).
- Scheme colours must be `#rgb` or `#rrggbb`; anything else falls back to the paper colour, so the custom scheme can never inject CSS.
- Login rate limiting: while a key (username or IP hash) has 5 failures in the last 15 minutes, attempts for it are refused without checking the password and are not recorded. A successful login clears the username's failures, not the IP's.
- After login, admins and editors go to the return address only when it is inside `/admin`, otherwise to `/admin`; users go back to the page they came from.
- The admin navigation also has a "Dashboard" item for admins and editors (the plan's list does not name it, but `/admin` is the dashboard).
- Dashboard counts show the whole site for administrators and only their own pages, images, blogs, posts and pending comments for editors.
- A placeholder Account screen was added in step 2.2 so a `user` has somewhere to land; step 2.3 fills it in.
- Account: one form for display name and password. The current password is required only when a new password is given. The session id is regenerated after a password change.
- Page delete is `POST /admin/pages/{id}/delete` (section 5 lists no URL for it).
- Page form: an empty slug is filled from the name and made unique (`-2`, `-3`; reserved words also count as taken). A typed slug is normalised with `slugify()` and refused with a message if reserved or taken. An empty title means the same as the name.
- `show_in_menu` is not on the page form, because menu visibility is an administrator setting (section 7); it is edited in Settings (step 6.1).
- Boxes within a row are moved with the same `direction=up|down` POST as rows; in the editor these show as left and right arrows.
- New boxes start with empty default content for their type; the "Add box" width list only offers widths that still fit, and the server checks again.
- The row alignment select submits on change via admin.js; a "Set" button is kept so it also works without JavaScript.
- Fixed box heights must be between 50 and 2000 pixels; text boxes take at most 50,000 characters.
- Embeds: besides the URL forms in section 6.6, `youtube.com/embed/...` and `m.youtube.com` are recognised. Iframes use `www.youtube.com` (the CSP host), aspect ratio 16:9 for video and 4:3 for maps, and fill the box when it has a fixed height. Only `http(s)` URLs are accepted; other recognised-nothing URLs become a plain link.
- When an embed has both raw HTML and a URL, the HTML is shown. An editor saving an embed box keeps any HTML an administrator put there; posting the `html` field at all as a non-admin gives 403.
- Image upload accepts several files at once (`images[]`). Images over 40 megapixels are refused to protect the host's memory; PHP's memory limit is raised for big images when the host allows it.
- JPEG orientation is read with `exif_read_data` when the `exif` extension exists, otherwise by reading the EXIF block directly (`exif` is not on the required list and is missing on the dev machine).
- GIF and WebP uploads are re-encoded to JPEG on a white background (animation is lost); medium and small sizes are never enlarged beyond the original width.
- Image routes not listed in section 5: `POST /admin/images` (upload), `POST /admin/images/{id}/alt`, `POST /admin/images/{id}/delete`.
- A POST bigger than PHP's `post_max_size` gets a clear "Upload too large" page (413) instead of a CSRF error.
- Image picker: the box form renders the newest 60 images as radio buttons (works without JavaScript); admin.js reloads the list from `/admin/images/picker?q=` when searching. The picker offers the same images as the library (admins all, editors their own), and the server only accepts those.
- Uploading inside the image box form is a separate small form that posts to `/admin/images` with `box_id`; the new image is put into the box straight away.
- Boxes in a row are top-aligned (`align-items: start`) rather than stretched to equal height, so a box without a fixed height really follows its content.
- `sizes` for image boxes is the box's share of the page width, or the full viewport below 700 px.
