# Decisions

Choices made where `PLAN.md` was ambiguous or silent. One line each.

- ~~The site is assumed to live at the web root.~~ Changed in 1.1.0 at the owner's request: the site may live at the web root or in a subfolder (see below).
- `robots.txt` is served directly by `.htaccess` as well, otherwise it would fall through to `index.php` and give 404.
- Composer `platform.php` is pinned to 8.2.0 so the committed `vendor/` works on any PHP 8.2+ host; PHPUnit 11.5 is used.
- `dev/router.php` serves static files itself (instead of returning false) so the security headers are set on them too, as Apache does.
- `slugify()` follows the test case in step 1.2 (`Blåbærsyltetøy` → `blabaersyltetoy`): æ → ae, ø → o, å → a. Section 9's "ae oe aa" contradicts that example; the example wins.
- `app/bootstrap.php` sets everything up; `index.php` then dispatches the request. This lets the installer include the bootstrap without dispatching.
- Small extra core classes not in the folder list: `App` (state and request cycle), `Request`, `Response`, `HttpException`, and `app/routes.php` for the route table.
- An unknown path gives 404; a path that only has routes for another method gives 405. GET `/logout` gives 404, because a GET for any single segment is looked up as a page slug.
- Sessions start only after installation; the session lifetime is the browser session, server-side garbage collection after 24 hours of inactivity.
- The security headers other than CSP come from `.htaccess` (as section 8 says) and `dev/router.php`, not from PHP, to avoid duplicate headers.
- Referential integrity is handled in the Repos (deletes run in transactions), not with SQL foreign-key constraints, so deletes follow the rules of section 6.12 exactly.
- Table and column names follow section 4 exactly. Note for a later MySQL driver: `rows` and `key` are reserved words there and will need quoting.
- Login attempts get their own repo, `Repos/LoginAttempts.php`, because all SQL must live in a repo. `Repos/Repo.php` is a small shared base class.
- Usernames are stored and compared in lower case, so login is case-insensitive.
- Deleting a user moves their pages, blogs, images and posts to the administrator who deletes them; their comments keep the author name but lose the user link.
- Published posts are shown regardless of `published_at` being in the future (scheduled publishing is a later feature).
- The `Schemes` class and the five scheme files were created in step 1.4 instead of 1.5, because the installer's site step needs the list of built-in schemes.
- The installer logic lives in `app/Installer.php` (testable); `install/index.php` is only the page flow. It has its own `install/install.css` and `install/install.js` (no inline scripts, because of the CSP).
- The installer stores only the password hash in the session between steps, never the plain password.
- If `installed.lock` is missing but the database already contains users, the installer refuses to continue instead of overwriting the site.
- Usernames: 3 to 40 letters, digits, dots, dashes or underscores. Display names: at most 80 characters.
- The page's `title` is used for `<title>` and as a visually hidden `<h1>`; visible headings come from the boxes (the installer's welcome box already has its own heading). This keeps one `<h1>` per page.
- The home page is reachable both as `/` and as `/{its slug}`; the menu links to `/`.
- Row alignment: a row's grid gets only as many 1/12-wide columns as its boxes use, so `justify-content` can place them left, centre or right. Empty rows are not shown publicly.
- On narrow screens fixed heights are dropped for text boxes only (as the plan says); image, blog and embed boxes keep them.
- `--page-width` is written into the same `<style>` block as the scheme colours. `app/Frame.php` gathers the data for the public page frame (settings, menu, logo, footer).
- Scheme colours must be `#rgb` or `#rrggbb`; anything else falls back to the paper colour, so the custom scheme can never inject CSS.
- Login rate limiting: while a key (username or IP hash) has 5 failures in the last 15 minutes, attempts for it are refused without checking the password and are not recorded. A successful login clears the username's failures, not the IP's.
- After login, admins and editors go to the return address only when it is inside `/admin`, otherwise to `/admin`; users go back to the page they came from.
- The admin navigation also has a "Dashboard" item for admins and editors (the plan's list does not name it, but `/admin` is the dashboard).
- Dashboard counts show the whole site for administrators and only their own pages, images, blogs, posts and pending comments for editors.
- A placeholder Account screen was added in step 2.2 so a `user` has somewhere to land; step 2.3 fills it in.
- Account: one form for display name and password. The current password is required only when a new password is given. The session id is regenerated after a password change.
- Page delete is `POST /admin/pages/{id}/delete` (section 5 lists no URL for it).
- Page form: an empty slug is filled from the name and made unique (`-2`, `-3`; reserved words also count as taken). A typed slug is normalised with `slugify()` and refused with a message if reserved or taken. An empty title means the same as the name.
- `show_in_menu` is not on the page form, because menu visibility is an administrator setting (section 7); it is edited in Settings (step 6.1).
- Boxes within a row are moved with the same `direction=up|down` POST as rows; in the editor these show as left and right arrows.
- New boxes start with empty default content for their type; the "Add box" width list only offers widths that still fit, and the server checks again.
- The row alignment select submits on change via admin.js; a "Set" button is kept so it also works without JavaScript.
- Fixed box heights must be between 50 and 2000 pixels; text boxes take at most 50,000 characters.
- Embeds: besides the URL forms in section 6.6, `youtube.com/embed/...` and `m.youtube.com` are recognised. Iframes use `www.youtube.com` (the CSP host), aspect ratio 16:9 for video and 4:3 for maps, and fill the box when it has a fixed height. Only `http(s)` URLs are accepted; other recognised-nothing URLs become a plain link.
- When an embed has both raw HTML and a URL, the HTML is shown. An editor saving an embed box keeps any HTML an administrator put there; posting the `html` field at all as a non-admin gives 403.
- Image upload accepts several files at once (`images[]`). Images over 40 megapixels are refused to protect the host's memory; PHP's memory limit is raised for big images when the host allows it.
- JPEG orientation is read with `exif_read_data` when the `exif` extension exists, otherwise by reading the EXIF block directly (`exif` is not on the required list and is missing on the dev machine).
- GIF and WebP uploads are re-encoded to JPEG on a white background (animation is lost); medium and small sizes are never enlarged beyond the original width.
- Image routes not listed in section 5: `POST /admin/images` (upload), `POST /admin/images/{id}/alt`, `POST /admin/images/{id}/delete`.
- A POST bigger than PHP's `post_max_size` gets a clear "Upload too large" page (413) instead of a CSRF error.
- Image picker: the box form renders the newest 60 images as radio buttons (works without JavaScript); admin.js reloads the list from `/admin/images/picker?q=` when searching. The picker offers the same images as the library (admins all, editors their own), and the server only accepts those.
- Uploading inside the image box form is a separate small form that posts to `/admin/images` with `box_id`; the new image is put into the box straight away.
- Boxes in a row are top-aligned (`align-items: start`) rather than stretched to equal height, so a box without a fixed height really follows its content.
- `sizes` for image boxes is the box's share of the page width, or the full viewport below 700 px.
- Blog delete is `POST /admin/blogs/{id}/delete`; new blogs are created with `POST /admin/blogs`. The blog edit screen lists the blog's posts (drafts first).
- Blog index entries show title, date, author and the first paragraph as plain text. Page numbers beyond the last page give 404.
- RSS feed: `dc:creator` for the author, `atom:link rel="self"`, the full rendered post body as `description` (escaped), and site-relative links made absolute. Dates in the feed are UTC in RFC 822 form.
- Posts are created with `POST /admin/blogs/{id}/posts/new` and deleted with `POST /admin/posts/{id}/delete`. The post slug `feed` is reserved (it would clash with the feed URL).
- The publish date is entered as local time in the site's timezone (`datetime-local`). Saving the form with the date unchanged keeps the stored value exactly; an empty date on a published post becomes "now" only if it has never been published. Unpublishing keeps the date.
- New posts default to comments open to "anyone"; the post page's meta description is the first paragraph of the body.
- Tests run against an in-memory database set in `tests/bootstrap.php`, never against `data/`.
- A blog box may show any blog, not only the editor's own: it only lists published (public) posts. The post count is limited to 1 to 20.
- The blog box heading is the blog title, linking to the blog.
- Comment spam controls: the honeypot field is `website`, hidden off-screen; the form time stamp is signed with the site secret (so it cannot be faked) and accepted when 3 seconds to 24 hours old. "URLs" are counted as `http(s)://...` and `www....`. Rejected bots get a generic message.
- Pending comments are shown on the post page to admins, the post's author and the blog's owner (the owner may moderate them per section 7).
- Logged-in commenters do not enter a name: their display name is used.
- Comment actions are `POST /admin/comments/{id}/approve` and `POST /admin/comments/{id}/delete`, used both from `/admin/comments` and from the post page (a hidden `return` field decides where to go back). Delete is allowed for moderators and for the comment's own (logged-in) author.
- `/admin/comments` shows all pending comments (oldest first) and the 50 newest approved ones.
- Users: created with `POST /admin/users`, deleted with `POST /admin/users/{id}/delete`. Usernames follow the installer's rules; new users must have a password of at least 10 characters.
- An administrator cannot delete their own account (to avoid locking themselves out mid-session); a deactivated user's open session ends on their next request.
- Settings: the menu table saves visibility with `POST /admin/settings/menu` and moves pages with `POST /admin/settings/menu/{id}/move`. Menu order counts every page, including hidden ones.
- The settings preview box follows whichever scheme is chosen; for "Custom" it follows the colour inputs live. "Start from current scheme" copies the chosen built-in scheme into the custom inputs and selects "Custom" (in the browser with JavaScript; without it the server does the same and shows the form again unsaved).
- The custom scheme is always saved with the settings form, so switching back to a built-in scheme keeps the custom colours for later.
- The tagline may have at most 200 characters and the footer at most 10,000; the time zone list is PHP's list of identifiers.
- Backup: the database is copied with `VACUUM INTO` (consistent snapshot), falling back to a file copy under `BEGIN IMMEDIATE` on old SQLite versions. The zip is built in `data/` (writable and blocked from the web), streamed to the browser and deleted; leftovers older than an hour are removed on the next backup. The date in the file name uses the site's timezone.
- The release zip leaves out the development documents (`CLAUDE.md`, `PLAN.md`, `DECISIONS.md`) besides the files the plan lists. `dev/router.php` can serve an extracted zip with `ANGELMA_ROOT=<folder>`.
- `Options` and `DirectoryIndex` are not used in the `.htaccess` files: on hosts that do not allow those overrides they would break the whole site with a 500 error. Directory listings are prevented instead by the rewrite rules, the blocked folders and empty `index.html` files in `assets/` and `uploads/`.
- Apache is not installed on the development machine, so the `.htaccess` files were checked by reading and through the `dev/router.php` emulation only; the first real Apache run will be on the host.
- Review pass (step 6.4): static files (CSS, JS, images) also get the Content-Security-Policy, from `.htaccess` for those file types only so PHP pages do not get it twice. The scheme `<style>` block is now printed with `e()` (it contains no characters `e()` changes), so `raw()` is used only for Markdown and the admin's raw embed HTML.
- Review pass: verified with a 145-check role matrix (anonymous, user, two editors, admin) over every row of section 7, a CSRF check of all 34 POST routes, headless-browser checks of all admin JavaScript, and layouts at 360, 700 and 1400 px.
- Subfolder support (1.1.0, requested by the owner after 1.0.0): the site's URL path is detected from the script's URL (`/folder/index.php` or `/folder/install/index.php` → `/folder`), or set with `'base_path' => '/folder'` in `data/config.php`. `url()` adds it to every link, incoming paths are read without it, the session cookie is limited to it, and admin.js reads it from `<meta name="base-path">`. Markdown links and images starting with `/` get the folder in front, so content written as `[About](/about)` keeps working when the site moves between the root and a subfolder. `dev/router.php` emulates a subfolder with `ANGELMA_BASE=/folder`.
- Licence: GPL-3.0 (`GPL-3.0-only` in `composer.json`), as chosen by the owner; the licence text is the `LICENSE` file from the GitHub repository. Commits use the owner's GitHub noreply address so no private email is published.
- Page order (1.1.1, requested by the owner): the menu order was only editable at the bottom of Settings and was hard to find, while the arrows on the page edit screen move rows and boxes. The pages list now shows the same up and down arrows for administrators (`POST /admin/pages/{id}/move`, not in section 5); the Settings menu table is kept as section 6.1 asks. Editors see no arrows, because menu order is an administrator setting (section 7).
- Container boxes (1.2.0, step 7.1): nested rows keep `page_id` set, so every query by page, the owner checks and the image and blog usage checks keep working unchanged; `parent_box_id` is null for a page's own rows and a row's `position` counts within its parent. `Rows::forPage()` still returns every row of the page, nested ones included; `forPageByParent()` groups them for the views.
- Containers draw nothing (no padding, background or border) and their last inner row has no bottom margin, so a container holding one full-width box looks exactly like that box alone. Inner rows reuse the `--col` width, which is a percentage of the container, so widths inside are shares of the container.
- Upgrades: migrations used to run only in the installer. Since 1.2.0 `App::db()` compares the stored schema version with `Db::SCHEMA_VERSION` on every request (one small query) and applies newer migration files, so uploading a new release over an installed site is enough. Two simultaneous first requests could both try the migration; the loser gets one error page and the next request works.
- Container editor (step 7.2): the layout editor renders rows through `admin/layout_rows.php`, which renders itself for the rows inside a container; a container box in the editor has a solid frame so nesting is visible. `POST /admin/boxes/{id}/rows` gives 404 for a box that is not a container. The "Add box" type list leaves out "Container" at the depth limit and the server refuses it with a message. A height posted for a container is ignored, not rejected.
- Checked in step 7.2 with curl and headless Chromium on a throwaway copy: a tall 6-wide box beside a 6-wide container with two stacked boxes and a container inside it, at 1200 and 600 px; the third nesting level is refused; an editor gets 403 on another owner's container; deleting a container removes everything inside it.
- Content ownership removed (1.3.0, step 8.1, at the owner's request): editors manage all content and administrators also manage the site (section 7). The created-by columns stay and are shown as "Created by"; deleting a user still hands their content to the deleting administrator so those names stay valid. `Auth::owns()` and `Auth::requireOwner()` are gone, and the repos lost their owner filters. Pending comments on a post page are shown to every editor.
- Workbench (1.3.0, step 9.1): a hidden page rather than a separate pool, so the layout editor, previews, nested containers and the usage checks work there unchanged. It is created on first use by `Workbench::page()` and remembered in the `workbench_page_id` setting (no migration). `Pages::all()` and `Pages::menu()` leave it out, so it never appears in the pages table, the Settings menu table or the home page selector; the server also refuses it as home page and refuses to delete it. Its slug is `workbench`, or `workbench-2` if a page already uses that. Its name and title come from the language file at creation.
- Moving boxes (1.3.0, step 9.2): `GET /admin/boxes/{id}/move-to` lists every row of every page in one select grouped by page, the workbench first, with rows inside containers labelled "Row 2 › Container 1 › Row 1", plus "New row at the end" per page; the box's own row, rows inside the box and full rows are left out. The move screen creates the workbench if it does not exist yet. A box goes to the end of the target row with the width chosen on the screen; the server checks width, self-containment and the depth rule (the target row's depth plus the container levels inside the moved box must stay below two). Each row's "Add box" area also offers "move here from the workbench" with the workbench's top-level boxes that fit, posting `box_id` to the same add-box route. `box_label()` in helpers.php gives the plain-text name of a box used in those lists.
- Deleting containers (1.3.0, step 9.3): the "Delete…" button of a container opens a confirmation screen (`GET /admin/boxes/{id}/delete`) with two POST buttons, since a browser confirm cannot offer a third choice; other boxes keep the confirm dialog. "Keep its boxes" moves every box directly inside the container to its own new row on the workbench, nested containers as whole units, then deletes the now empty container. The count shown on the screen includes boxes at any depth.
- Checked in phase 9 with curl on a throwaway copy: the workbench opens, builds and previews a container; boxes move from the workbench to a page and back, through the move screen and the "move here" form; moving a container into itself, into a full row or too deep is refused; a container with four boxes inside is deleted keeping three top-level ones on the workbench.
- Maintenance mode (1.4.0, step 10.1): a setting, not a file, so it is switched in Settings like everything else and survives updates. The check sits in `App::dispatch()` after the session starts, so logged-in editors pass; `/login`, `/logout`, `/admin`, `/install` and `/assets` are exempt. The notice is Markdown rendered like the footer. The bar for editors on the public site uses a fixed orange, not a scheme colour, since it is a warning for staff and not part of the design.
- Release tooling (step 10.2): `dev/build.sh` writes `angelma-<version>.zip.sha256` in sha256sum's format next to the zip; `dev/release.sh` refuses a dirty tree, takes the notes from the version's section of `CHANGELOG.md`, tags, pushes and creates the GitHub release with `gh`. `CHANGELOG.md` is shipped in the zip; like every `.md` file it is blocked from the web.
- Updater (1.4.0, step 10.3): the GitHub API is asked once a day (cached in the `update_check` setting) rather than scraping the releases page, because it gives the notes and the asset addresses, and the anonymous rate limit is far above that. Asset addresses must be under the configured download base of the repository, so a release whose download link points elsewhere is ignored. `curl_close()` is not called: PHP 8.5 deprecates it and the app turns deprecations into exceptions. The lock file is ignored after five minutes, so a crash in the middle of an update cannot lock the site out. "Restore previous version" copies `data/updates/previous` back with the same `apply()`, which also removes files the previous version did not have. The cached check is dropped after an install or a restore, since it was made by the other version.
- Checked in step 10.3 on a throwaway copy against a local stand-in for GitHub (release JSON, redirecting download links as GitHub does, a fake 9.9.9 release built from the tree): the dashboard notice, the screen with notes and checks, a 2268-file install in a third of a second with data and config intact, the "up to date" screen afterwards, the restore, a refused checksum, and the lock page including a stale lock.
